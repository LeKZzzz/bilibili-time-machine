# B 站时光机 · bilibili-time-machine

给 B 站设置一个截止时间，只看在此之前发布的内容。支持 Chrome Manifest V3 扩展和 Tampermonkey 用户脚本，保留 B 站原生页面样式。

工具只过滤当前仍可获取的内容，不恢复历史首页、已删除视频或当年的推荐排序。无法确认发布时间的内容会隐藏。

## 能做什么

| 功能 | 行为 |
| --- | --- |
| 视频与封面过滤 | 只展示发布时间严格早于截止时间 `T` 的视频，卡片和封面一起处理 |
| 评论过滤 | 过滤当前已加载的评论及楼中楼；父评论被隐藏时，依赖它的回复也会隐藏 |
| XML 弹幕过滤 | 按弹幕发送时间过滤；protobuf 分段弹幕尚未支持 |
| 搜索结果跨页补齐 | 当前页可见结果不足半页时，最多补取后两页的结果并去重，结束后恢复原页码和 URL |
| 收藏标签首页补位 | 根据选定收藏夹中视频的标签，寻找符合时间条件的候选，填充首页被过滤的位置 |
| 截止时间自动推进 | 启动后按真实经过的完整分钟向后推进，刷新页面后继续 |

支持视频详情、首页、分区、搜索、空间视频列表及动态页面，页面主机限定为 `www.bilibili.com`、`search.bilibili.com`、`space.bilibili.com`、`t.bilibili.com`。未知路由只保留设置入口。

## 安装

扩展与用户脚本任选其一，避免在同一页面重复运行。

### Tampermonkey 用户脚本（无需构建）

1. 在浏览器中安装并启用 Tampermonkey。
2. 打开 [Greasy Fork 发布页：B 站时光机](https://greasyfork.org/zh-CN/scripts/601594-b-%E7%AB%99%E6%97%B6%E5%85%89%E6%9C%BA)，点击“安装此脚本”，在 Tampermonkey 中确认安装。
3. 刷新已打开的 B 站页面。

升级用户脚本时，通过 Greasy Fork 发布页安装新版，或在 Tampermonkey 中检查更新。

### Chrome 扩展或自行构建

以下步骤用于从源码构建 Chrome 扩展或用户脚本，也可下载[自动构建](#自动构建)生成的产物。准备 Node.js 20/22 LTS 或兼容版本、npm 和 Git。公开发布的 `main` 分支不包含预先构建的 `dist/`，请先运行：

```sh
git clone https://github.com/LeKZzzz/bilibili-time-machine.git
cd bilibili-time-machine
npm ci
npm run build
```

`npm run build` 会先执行类型检查和测试，再生成扩展与用户脚本。

**Chrome 扩展**

1. 打开 Chrome 的扩展管理页，启用“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择项目中的 `dist/extension/` 目录。
3. 刷新已打开的 B 站页面。

**手动安装自行构建的用户脚本**

1. 在浏览器中安装 Tampermonkey。
2. 在 Tampermonkey 管理面板中新建脚本，用 `dist/userscript/bilibili-time-machine.user.js` 的内容替换默认模板并保存。
3. 刷新 B 站页面。

升级扩展时，重新构建后在扩展管理页点击“重新加载”，再刷新 B 站；升级自行构建的用户脚本时，在脚本编辑器中替换为新的构建内容并保存。

## 使用

1. 在 B 站页面点击“时光机”，打开设置面板。
2. 输入本地时区的截止日期和时间，开启过滤。
3. 需要恢复完整页面时，关闭过滤并刷新页面，让 B 站重新请求内容。

日期和时间分开设置。“填入当前时间”位于输入框下方的快捷按钮行右侧，只填入当前本地时、分、秒，保留已选日期；快捷按钮“现在”则同时更新日期和时间。窄屏下按钮可自动换行，仍保持右对齐。主面板修改后自动保存，开启自动推进时，手动调整时间会重新开始计时。

例如，将 `T` 设为 `2020-01-01 00:00:00`，只有发布时间早于这一时刻的内容可以展示；恰好等于 `T`、晚于 `T` 或无法确认时间的内容会隐藏。设置支持精确到秒。

高级设置中的补请求预算用于确认已出现视频的发布时间：默认每次页面或路由最多补取 20 个视频，可设置为 0–100，并发上限为 3。预算耗尽或请求失败后仍无法确认时间的卡片会继续隐藏。

### 收藏标签首页补位

这项功能默认关闭，仅填充首页因时间过滤隐藏的卡片位置，保留原有可见卡片及其顺序。

1. 在首页打开时光机面板，开启独立的“收藏标签补位”。
2. 点击“管理收藏夹”，在二级面板中点击名称选中或取消，蓝色表示已选。列表显示当前账号自己创建的全部收藏夹。
3. 在管理面板中设置收藏夹数量上限和每夹视频上限，点击“保存”统一生效；取消、返回或按 Escape 不保存本次调整。
4. 点击“刷新收藏标签”更新偏好，点击“查看标签”查看标签列表。设置旁的问号支持悬停或键盘聚焦查看说明。

收藏夹名称列表按账号缓存，打开时优先使用缓存。新建、删除或重命名收藏夹后，在管理面板中点击“刷新收藏夹列表”；这不会刷新收藏视频标签。关闭补位后收起相关操作，不能获取或刷新列表，已有缓存和选择会保留。

标签评分结合出现频次（60%）和收藏时间新鲜度（40%）。每轮使用评分最高的 5 个标签，先让不同标签各提供一条，再按权重补齐；空位较少时，后续批次轮换起始标签。卡片上的“收藏标签补位：标签名”说明本轮实际命中的来源。

工具优先使用缓存，候选数量或标签覆盖不足时，每轮最多搜索 5 次。先轮询高分标签，仍缺候选且预算未用完时继续后续页。实际搜索期间显示一条“正在搜索补位视频…”提示，搜索结束后关闭；缓存足够时不显示。各标签独立推进页码，到末页或空页后在下一轮回到第 1 页，保留已推送视频的去重历史。首页仍有空位时，向下滚动停稳会开启下一轮，即使没有加载新卡片也能继续；不会因轮播、面板变化或持续停留自动反复搜索。每轮预算用完后可能仍有空位，下一次下滑再继续，不放宽截止时间。

收藏夹默认最多选择 3 个、每夹读取 50 条，可配置为 1–10 个收藏夹和每夹 1–200 条。所有选中项都会参与读取；达到数量上限后需取消其他选择或提高上限。未开启功能或未选择收藏夹时，不读取收藏内容、不发起标签搜索。

降低上限使已选数量超限时，管理面板会阻止保存并提示调整。旧配置若已超限，补位会暂停，保存符合上限的选择后再继续，不会悄悄只读取一部分收藏夹。保存的选择或每夹视频上限发生变化后，收藏标签按新设置重建。

### 缓存与刷新

收藏夹名称列表按 B 站 UID 分区保存在同源 localStorage 中，手动刷新成功后更新，失败保留旧列表；浏览器存储不可用时仅保留当前页面内存。加载时仍会查询当前账号 UID，命中缓存后不请求收藏夹列表。收藏标签、搜索候选和补位历史按 UID 分区保存在浏览器本地 IndexedDB 中：

| 数据 | 有效期 | 每账号上限 |
| --- | --- | --- |
| 收藏标签快照 | 24 小时 | 100 个评分标签 |
| 搜索候选 | 7 天 | 500 条 |
| 已补位视频历史 | 30 天 | 1000 条 |

快照在读取时检查有效期，过期后重建；没有独立的后台定时刷新任务。“已提交收藏标签刷新请求”表示请求已提交，不代表读取已经完成。页码和起始标签随有效快照保存，快照过期重建后不保证保留进度。

缓存可在同源页面间跨刷新、标签页和路由复用，不同 B 站子域名不共享。IndexedDB API 缺失时只使用当前页面内存。当前候选由补位功能发起的搜索产生，尚未收集用户搜索页已经加载的结果。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 页面没有“时光机”入口 | 确认扩展或脚本已启用、当前主机受支持；重新加载扩展后刷新页面 |
| 首页没有补位 | 确认位于 `www.bilibili.com/`，时间过滤与补位均已开启、已选择收藏夹，并存在被隐藏的卡片；没有符合时间且未推送过的候选时会留空 |
| 提示“过滤器无法验证当前内容，相关内容已隐藏。” | 普通过滤无法确认内容时间或补请求失败；相关内容继续隐藏，可调整补请求预算后重试 |
| 提示“收藏标签补位失败，本轮已停止。” | 收藏、搜索或存储链路失败；原有时间过滤继续工作，可稍后手动刷新收藏标签重试 |
| 升级后仍显示旧内容或旧界面 | 仅刷新 B 站不会重新加载扩展；在扩展管理页重新加载实际使用的生产或开发目录，再刷新页面 |
| 关闭过滤后内容没有全部恢复 | 已在响应中被过滤的数据需要重新获取，请刷新页面 |

评论过滤只覆盖当前加载范围，不会自动翻完全部历史评论；XML 以外的弹幕格式、所有无限滚动批次及部分 B 站页面变体仍需进一步验证。

## 开发与反馈

项目使用 TypeScript、Vite、Vitest 和 jsdom。设置界面保留原生 TypeScript 交互：`src/ui/panel.ts` 负责面板结构与事件，`src/ui/panel.css` 集中维护样式；`postcss.config.js` 使用 Tailwind CSS 与 daisyUI 编译 CSS，再通过 `?inline` 引入并注入 Shadow DOM，不从 CDN 加载。扩展与用户脚本共享过滤核心：

| 目录 | 内容 |
| --- | --- |
| `src/core/` | 时间判定、标签评分、候选选择和存储逻辑 |
| `src/page/` | 页面响应过滤与首屏状态处理 |
| `src/runtime/` | 双运行时适配、消息桥和页面生命周期 |
| `src/routes/`、`src/ui/` | 支持路由、设置面板和提示 |
| `extension/`、`userscript/` | 扩展清单和用户脚本入口 |
| `tests/` | 固定样本、单元测试和集成测试 |

验证与构建命令：

```sh
npm run typecheck
npm test -- --run
npm run build
npm run build:dev
```

生产产物位于 `dist/extension/` 和 `dist/userscript/`；开发产物位于 `dist/dev/extension/` 和 `dist/dev/userscript/`。开发版自动向当前浏览器控制台输出带 `[时光机]` 前缀的脱敏日志，生产版不包含项目诊断日志。日志不上传，不包含响应正文、评论文本、Cookie 或完整 URL。

欢迎通过 [Issues](https://github.com/LeKZzzz/bilibili-time-machine/issues) 反馈兼容性问题，提供浏览器版本、安装方式、页面类型、复现步骤和脱敏错误信息；提交修改时请附上相关验证结果。

### 自动构建

`.github/workflows/build.yml` 在每次推送到 GitHub 时运行，也可在 [Actions](https://github.com/LeKZzzz/bilibili-time-machine/actions) 中选择 **Build → Run workflow** 手动触发。工作流使用 Node.js 22，依次执行 `npm ci`、`npm run build`（含类型检查和全部测试）及 `npm run build:dev`，成功后上传两份构建产物：

| Artifact | 内容 |
| --- | --- |
| `bilibili-time-machine-release` | 生产版扩展和用户脚本，不含项目诊断日志 |
| `bilibili-time-machine-dev` | 开发版扩展和用户脚本，包含本地脱敏日志 |

登录 GitHub，打开对应分支的一次成功运行，在 **Artifacts** 区域下载并解压。两份压缩包均包含 `extension/` 和 `userscript/`：Chrome 加载已解压扩展时选择 `extension/`，手动安装油猴脚本时使用 `userscript/bilibili-time-machine.user.js`。工作流只提供构建下载，不会自动推送代码、创建 Release 或发布到 Greasy Fork。
