# B 站时光机 · bilibili-time-machine

给 B 站设置一个截止时间，只看在此之前发布的内容。支持 Chrome Manifest V3 扩展和 Tampermonkey 用户脚本，保留 B 站原生页面样式。

工具只过滤当前仍可获取的内容，不恢复历史首页、已删除视频或当年的推荐排序。无法确认发布时间的内容会隐藏。

## 能做什么

| 功能 | 行为 |
| --- | --- |
| 视频与封面过滤 | 只展示发布时间严格早于截止时间 `T` 的视频，卡片和封面一起处理 |
| 评论过滤 | 过滤当前已加载的评论及楼中楼；父评论被隐藏时，依赖它的回复也会隐藏 |
| XML 弹幕过滤 | 按弹幕发送时间过滤；protobuf 分段弹幕尚未支持 |
| 搜索结果跨页补齐 | 当前页可见结果不足半页时，最多补取后两页的结果并去重，结束后恢复原页码和 URL |
| 收藏标签首页补位 | 根据选定收藏夹中视频的标签，寻找符合时间条件的候选，填充首页被过滤的位置 |
| 截止时间自动推进 | 启动后按真实经过的完整分钟向后推进，刷新页面后继续 |

支持视频详情、首页、分区、搜索、空间视频列表及动态页面，页面主机限定为 `www.bilibili.com`、`search.bilibili.com`、`space.bilibili.com`、`t.bilibili.com`。未知路由只保留设置入口。

## 安装

### 1. 从源码构建

准备 Node.js 20/22 LTS 或兼容版本、npm 和 Git。仓库不包含预先构建的 `dist/`，请先运行：

```sh
git clone https://github.com/LeKZzzz/bilibili-time-machine.git
cd bilibili-time-machine
npm ci
npm run build
```

`npm run build` 会先执行类型检查和测试，再生成扩展与用户脚本。

### 2. 选择一种安装方式

**Chrome 扩展**

1. 打开 Chrome 的扩展管理页，启用“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择项目中的 `dist/extension/` 目录。
3. 刷新已打开的 B 站页面。

**Tampermonkey 用户脚本**

1. 在浏览器中安装 Tampermonkey。
2. 在 Tampermonkey 管理面板中新建脚本，用 `dist/userscript/bilibili-time-machine.user.js` 的内容替换默认模板并保存。
3. 刷新 B 站页面。

两种方式任选其一，避免在同一页面重复运行。升级扩展时，重新构建后在扩展管理页点击“重新加载”，再刷新 B 站；升级用户脚本时，在脚本编辑器中替换为新的构建内容并保存。

## 使用

1. 在 B 站页面点击“时光机”，打开设置面板。
2. 输入本地时区的截止日期和时间，开启过滤。
3. 需要恢复完整页面时，关闭过滤并刷新页面，让 B 站重新请求内容。

例如，将 `T` 设为 `2020-01-01 00:00:00`，只有发布时间早于这一时刻的内容可以展示；恰好等于 `T`、晚于 `T` 或无法确认时间的内容会隐藏。设置支持精确到秒。

高级设置中的补请求预算用于确认已出现视频的发布时间：默认每次页面或路由最多补取 20 个视频，可设置为 0–100，并发上限为 3。预算耗尽或请求失败后仍无法确认时间的卡片会继续隐藏。

### 收藏标签首页补位

这项功能默认关闭，仅填充首页因时间过滤隐藏的卡片位置，保留原有可见卡片及其顺序。

1. 在首页打开“高级设置”，开启“收藏标签首页补位”。
2. 刷新收藏夹列表，从自动获取的名称选项中选择一个或多个收藏夹。
3. 按需设置收藏夹数量和每夹视频条数；点击“立即刷新收藏标签”更新偏好，点击“查看当前标签”查看标签列表。

标签评分结合出现频次（60%）和收藏时间新鲜度（40%）。每轮使用评分最高的 5 个标签，先让不同标签各提供一条，再按权重补齐；空位较少时，后续批次轮换起始标签。卡片上的“收藏标签补位：标签名”说明本轮实际命中的来源。

工具优先使用缓存，候选数量或标签覆盖不足时，每轮最多搜索 5 次、每个标签 1 页。各标签独立推进页码，到末页或空页后在下一轮回到第 1 页，保留已推送视频的去重历史。同一批原生卡片和设置只执行一轮自动搜索，不因轮播或面板变化反复请求。

收藏夹默认最多读取 3 个、每夹 50 条，可配置为 1–10 个收藏夹和每夹 1–200 条。未开启功能或未选择收藏夹时，不读取收藏内容、不发起标签搜索。

### 缓存与刷新

收藏相关数据按 B 站 UID 分区，保存在浏览器本地 IndexedDB 中：

| 数据 | 有效期 | 每账号上限 |
| --- | --- | --- |
| 收藏标签快照 | 24 小时 | 100 个评分标签 |
| 搜索候选 | 7 天 | 500 条 |
| 已补位视频历史 | 30 天 | 1000 条 |

快照在读取时检查有效期，过期后重建；没有独立的后台定时刷新任务。“已提交收藏标签刷新请求”表示请求已提交，不代表读取已经完成。页码和起始标签随有效快照保存，快照过期重建后不保证保留进度。

缓存可在同源页面间跨刷新、标签页和路由复用，不同 B 站子域名不共享。IndexedDB API 缺失时只使用当前页面内存。当前候选由补位功能发起的搜索产生，尚未收集用户搜索页已经加载的结果。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 页面没有“时光机”入口 | 确认扩展或脚本已启用、当前主机受支持；重新加载扩展后刷新页面 |
| 首页没有补位 | 确认位于 `www.bilibili.com/`，时间过滤与补位均已开启、已选择收藏夹，并存在被隐藏的卡片；没有符合时间且未推送过的候选时会留空 |
| 提示“过滤器无法验证当前内容，相关内容已隐藏。” | 普通过滤无法确认内容时间或补请求失败；相关内容继续隐藏，可调整补请求预算后重试 |
| 提示“收藏标签补位失败，本轮已停止。” | 收藏、搜索或存储链路失败；原有时间过滤继续工作，可稍后手动刷新收藏标签重试 |
| 升级后仍显示旧内容或旧界面 | 仅刷新 B 站不会重新加载扩展；在扩展管理页重新加载实际使用的生产或开发目录，再刷新页面 |
| 关闭过滤后内容没有全部恢复 | 已在响应中被过滤的数据需要重新获取，请刷新页面 |

评论过滤只覆盖当前加载范围，不会自动翻完全部历史评论；XML 以外的弹幕格式、所有无限滚动批次及部分 B 站页面变体仍需进一步验证。

## 开发与反馈

项目使用 TypeScript、Vite、Vitest 和 jsdom。扩展与用户脚本共享过滤核心：

| 目录 | 内容 |
| --- | --- |
| `src/core/` | 时间判定、标签评分、候选选择和存储逻辑 |
| `src/page/` | 页面响应过滤与首屏状态处理 |
| `src/runtime/` | 双运行时适配、消息桥和页面生命周期 |
| `src/routes/`、`src/ui/` | 支持路由、设置面板和提示 |
| `extension/`、`userscript/` | 扩展清单和用户脚本入口 |
| `tests/` | 固定样本、单元测试和集成测试 |

验证与构建命令：

```sh
npm run typecheck
npm test -- --run
npm run build
npm run build:dev
```

生产产物位于 `dist/extension/` 和 `dist/userscript/`；开发产物位于 `dist/dev/extension/` 和 `dist/dev/userscript/`。开发版自动向当前浏览器控制台输出带 `[时光机]` 前缀的脱敏日志，生产版不包含项目诊断日志。日志不上传，不包含响应正文、评论文本、Cookie 或完整 URL。

欢迎通过 [Issues](https://github.com/LeKZzzz/bilibili-time-machine/issues) 反馈兼容性问题，提供浏览器版本、安装方式、页面类型、复现步骤和脱敏错误信息；提交修改时请附上相关验证结果。
