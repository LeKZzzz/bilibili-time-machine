# B 站时光机

**按过去的时间逛 B 站，也能把喜欢的动画连着看。**

B 站时光机可以按截止时间筛选视频与评论，或按片单连续播放动画，保留 B 站原生页面与播放器。支持 Chrome 扩展和 Tampermonkey 用户脚本。

[English](README.en.md) · [下载扩展](https://github.com/LeKZzzz/bilibili-time-machine/releases) · [安装油猴脚本](https://greasyfork.org/zh-CN/scripts/601594-b-%E7%AB%99%E6%97%B6%E5%85%89%E6%9C%BA) · [反馈问题](https://github.com/LeKZzzz/bilibili-time-machine/issues)

## 可以做什么

| 想做的事 | 对应功能 |
| --- | --- |
| 只看某个时间之前的内容 | 设置截止时间，过滤视频卡片、已加载评论与 XML 弹幕；截止时间也可以自动向前走 |
| 像看电视一样轮着看动画 | 在“动画时光机”中编排作品与分集，轮播或顺播，下次继续观看 |
| 在动画之间穿插公益短片 | 自定义广告片单和间隔；动画允许中途插播，普通观看只在片尾插播，随时可跳过 |
| 让过滤后的首页少留空位 | 从自己的收藏夹提取兴趣标签，寻找符合截止时间的视频，只填空位、不替换已显示内容 |

**时间过滤和播放功能独立。** 看动画不需要设置截止时间或开启过滤。开启过滤时，当前连播的动画可以正常播放，推荐和评论仍按原设置过滤。

动画连播默认每累计观看 **20 分钟**插播公益短片。可以随时跳过，也可以关闭“动画中途插播”并保存设置。

它使用当前仍可访问的 B 站内容，不恢复历史首页、已删除视频或当年的推荐排序，也不绕过会员和地区限制。

## 安装

**扩展与用户脚本任选其一，不要同时启用。** 普通使用不需要 Node.js，也不需要自己构建源码。

### Chrome 扩展

1. 在 [GitHub Releases](https://github.com/LeKZzzz/bilibili-time-machine/releases) 的 **Assets** 中下载 `bilibili-time-machine-extension-vX.Y.Z.zip` 并解压。
2. 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择**直接包含 `manifest.json`** 的目录，刷新 B 站页面，点击“时光机”。

升级时加载新版目录，确认扩展版本后再刷新 B 站。不要选择 Release 中的 **Source code** 压缩包，它不是安装包。

### Tampermonkey 用户脚本

1. 安装并启用 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开 [Greasy Fork：B 站时光机](https://greasyfork.org/zh-CN/scripts/601594-b-%E7%AB%99%E6%97%B6%E5%85%89%E6%9C%BA)，点击“安装此脚本”，在 Tampermonkey 中确认。
3. 刷新 B 站页面，点击“时光机”。后续可在 Tampermonkey 中检查更新。

**动画与广告功能需要 `v0.3.0` 或更新版本。** Greasy Fork 与 GitHub 分别发布，版本可能不同。如果 Greasy Fork 尚未更新，可从 GitHub Release 下载 `bilibili-time-machine.user.js`，导入 Tampermonkey；`bilibili-time-machine-userscript-vX.Y.Z.zip` 解压后也是同一份脚本。

## 看动画

打开 **“时光机”**，在顶部选择 **“动画时光机”** 标签页；可随时切换到并列的 **“截止时间过滤”** 标签页。

1. 可以先试内置片单，也可以点击“添加作品”，粘贴 B 站视频或番剧链接，点击“获取分集”，选择需要的分集并确认添加。只想加入一个视频时，也可填写名称和链接后直接添加。
2. 选择“轮播 · 每部各播一集”或“顺播 · 看完一部再下一部”，点击“保存设置”，再点击“从头播放”。
3. 想停下来时点击“暂停”；结束本次连播时点击“退出连播”，保留进度。下次打开“动画时光机”后点击“继续观看”。

点击作品可查看分集，或通过“添加分集”增加内容。每部作品至少需要一个分集；增删后记得点击“保存设置”。

“继续观看”会优先从当前页面中已在片单里的分集和观看位置继续；当前视频不在片单里时，恢复上次保存的进度。“从头播放”则从片单第一集的开头开始。

默认片单包含 **31 部动画**，包括《黑猫警长》《虹猫蓝兔七侠传》《喜羊羊与灰太狼》《数码宝贝》《蓝精灵》《鼹鼠的故事》等。实际集数取决于可用片源，不保证全集。

<details>
<summary>播放顺序、续播与分集管理</summary>

假设作品 A 有两集、作品 B 有三集：

| 顺序 | 播放示例 |
| --- | --- |
| 轮播 | A1 → B1 → A2 → B2 → B3 → 下一轮 A1 |
| 顺播 | A1 → A2 → B1 → B2 → B3 → 下一轮 A1 |

整份片单播完后循环。播放中可以切换轮播／顺播并保存：当前这一集继续播放，观看位置和广告计时保留，下一集按新顺序播放。暂停或插播广告时保存顺序，不会自动恢复播放或跳过广告。增删作品、分集前需先退出连播。

刷新页面、重新打开浏览器或新开标签页后，需要主动点击“继续观看”。已保存进度的分集尚未开始播放时，会保留原来的观看位置；新选中的分集尚未加载时，从开头开始。

连播中手动切到片单内的其他分集，会从新选择的位置继续，后续按片单顺序播放。同页切换和当前窗口的跨页面跳转都无需再次点击“继续观看”。切到片单外的视频会结束连播；主动退出后不会自动重新开始。

添加作品或分集时，可以获取视频分 P、视频合集和番剧 `ep` / `ss` 链接中的正片，预览后选择需要的分集。没有分 P 或选集列表的长视频会作为一个视频加入，不会自动拆分。

打开“动画时光机”时，会尝试补全尚未修改的内置作品并保存。可以取消补全；获取失败时仍保留已有分集，手动修改或删除的作品不会被自动恢复，也不会用新默认片单覆盖已有片单。

</details>

## 设置公益广告

在“动画时光机”标签页中设置广告片单、插播开关和间隔。内置 **22 条公益广告**，可自行增删。

点击“添加公益广告”，填写链接（名称选填）后确认，再点击“保存设置”。只会加入指定视频，不会自动添加整份合集。取消添加不会改动片单。

| 设置 | 默认 | 什么时候播放 | 广告结束或跳过后 |
| --- | --- | --- | --- |
| 动画中途插播 | 开启 | 累计观看达到间隔后，暂停当前动画并插播 | 从暂停位置继续动画 |
| 普通观看片尾插播 | 关闭 | 达到间隔后等待，当前视频结束才插播 | 交还 B 站原生连播；“播完暂停”仍保持暂停 |

**广告加载和播放时都可以点击“跳过广告”**。每次最多播放 60 秒，然后回到原视频；没有播完的广告会在下次插播时接着播放。

<details>
<summary>广告内容、播放时长与计时规则</summary>

内置片单包括央视及国内怀旧短片，以及泰国、英国、巴西、澳大利亚、韩国和 WWF 等国外或国际主题短片，涵盖家庭关怀、诚信礼让、环保、交通安全、防溺水、禁烟和反校园暴力。

广告覆盖在当前播放器上，周围变暗。加载失败时会关闭广告，不会立即播放另一条。

每次最多播放 60 秒，暂停、缓冲和拖动进度不计入。长广告未播完时先返回正片，下次插播时从上次的位置继续，完整播完才换下一条。手动跳过或退出也会保留已保存的广告进度；刷新后不会立即弹出广告。

两种模式共用广告片单与间隔，但分别计时；默认间隔为 **20 分钟实际播放时间**。暂停、缓冲、拖动进度和广告本身不计入，倍速也不会让计时加快。普通观看到点后不会中途打断正片，也不会积攒多条待播广告。

</details>

## 按过去的时间浏览

打开“时光机”，选择顶部的 **“截止时间过滤”** 标签页，输入本地时区的日期与时间，点击“应用时间”（或按 Enter），再点击“开启过滤”。

例如设置为 `2020-01-01 00:00:00`，只展示时间**严格早于**这一时刻的内容。视频按发布时间判断，评论和弹幕按发送时间判断；恰好等于截止时间、晚于截止时间或无法确认时间的内容会隐藏。

- 修改日期与时间后需要应用；“取消”恢复已生效的值。
- “现在”填入当前日期和时间；“填入当前时间”只改时、分、秒，保留日期。
- 自动推进按实际经过的完整分钟向前移动截止时间，刷新后继续，不覆盖正在编辑的草稿。
- 需要恢复完整页面时，点击“暂停过滤”后刷新页面。

支持首页、视频详情、分区、搜索、空间视频列表和动态页面。番剧可以加入片单播放，但番剧页面的时间过滤尚未完整支持。

### 用收藏偏好补充首页

此功能默认关闭。开启前需登录 B 站，并确保当前账号可以访问自己的收藏夹。

1. 开启“收藏偏好补充首页”，在“选择收藏夹”中选择来源并保存。
2. 返回首页查看结果。还有空位时，点击“继续寻找”，或向下滚动后停稳，开启下一轮。
3. 收藏内容变化后点击“更新收藏偏好”；“查看兴趣标签”可以查看从收藏视频中提取的标签。“刷新收藏夹列表”只更新可选收藏夹，不更新兴趣标签。

默认最多选择 **3 个收藏夹、每夹读取 50 个视频**，可在设置中调整。根据兴趣标签寻找符合截止时间的视频，只填空位，不替换已显示的视频；找不到合适视频时保留空位。

## 常见问题与限制

| 问题 | 说明或处理方式 |
| --- | --- |
| 找不到入口，或升级后还是旧界面 | 确认安装版本、启用状态和页面范围；扩展重新加载后还需刷新 B 站。不要同时启用脚本与扩展 |
| 动画没有自动播放 | 浏览器可能阻止自动播放，请按提示点击“继续播放”。刷新或重新打开后，用“继续观看”恢复上次进度 |
| 内置作品未能获取分集 | 已有分集仍可使用。点击作品进入详情，选择“添加分集”，重新获取并选择需要的分集，确认后保存设置 |
| 番剧被跳过 | 只能试看、无权播放或已失效的分集会跳过；整份片单均不可用时停止。需要大会员的内容仍需相应账号权限 |
| 首页仍有空位 | 确认已在首页开启时间过滤和“收藏偏好补充首页”，并选择收藏夹。没有符合时间要求且未重复的视频时，会保留空位 |
| 内容因无法确认时间而隐藏 | 可在高级设置中适当提高“发布时间查询上限”，然后刷新页面重试；仍无法确认时间的内容会继续隐藏 |
| 退出或换安装方式后进度不一致 | 退出会保存进度，但扩展与用户脚本的存储不互通；浏览器强制终止可能丢失最后尚未保存的几秒 |

评论只处理已加载内容，不自动翻完历史评论；弹幕目前只支持 XML，不支持 protobuf 分段弹幕。B 站页面和播放器变动也可能影响兼容性，不能保证覆盖全站。

跨页面切换分集可能退出全屏。不同浏览器、安装方式和片源的兼容性可能有所差异；遇到问题时，请提供安装方式、浏览器版本和复现步骤。当前已验证和待验证的情况见[版本与兼容性](#版本与兼容性)。

<details>
<summary>页面范围与推荐规则</summary>

时间过滤作用于 `www.bilibili.com`、`search.bilibili.com`、`space.bilibili.com` 和 `t.bilibili.com`。搜索页过滤后不足半页时，会最多补充后两页的结果并去重，保留原页码和 URL。

首页补充的视频按兴趣标签随机选择并去重，每轮最多搜索 5 次。没有合适结果时保留空位，不放宽截止时间。

内置作品获取分集失败后会保留当前结果，不会每次打开都重复尝试；可以通过“添加分集”重新获取。

</details>

## 数据保存与隐私

播放设置、片单和续播进度保存在当前安装方式的本地存储中，不会在扩展与用户脚本之间自动同步。收藏偏好按 B 站账号区分；未开启“收藏偏好补充首页”或未选择收藏夹时，不读取收藏内容，也不根据兴趣标签搜索视频。

<details>
<summary>存储、缓存与诊断细节</summary>

- 用户脚本使用 GM 存储，扩展使用 `chrome.storage.local`。播放与过滤配置分开保存。
- 收藏夹名称使用站点 `localStorage`；兴趣标签、待推荐视频和推荐历史使用 `IndexedDB`。同源页面可复用，不同 B 站子域不共享；缺少 IndexedDB 时退回当前页面内存。
- 兴趣标签缓存有效期为 24 小时，最多保留 100 个；待推荐视频为 7 天、500 个；推荐历史为 30 天、1000 条，均按账号区分。缓存到期后不保证永久去重。
- 发布时间查询默认每页或路由最多 20 个视频，可设为 0–100，并发上限为 3。收藏来源可设为 1–10 个收藏夹，每夹读取 1–200 个视频。
- 开发构建只向当前浏览器控制台输出脱敏日志，不上传；不含响应正文、评论文本、Cookie 或完整 URL。生产构建不包含项目诊断日志。

</details>

### 从源码构建

需要 **Node.js 22**、npm 和 Git。下面从 `dev` 构建本文介绍的开发版；需要已发布版本的源码时，请使用对应 Release 的 tag。

```sh
git clone https://github.com/LeKZzzz/bilibili-time-machine.git
cd bilibili-time-machine
git switch dev
npm ci
npm run build
```

构建先运行类型检查与全部测试，再生成 `dist/extension/` 和 `dist/userscript/bilibili-time-machine.user.js`。按上面的安装步骤加载即可；重新构建后需要重新加载扩展或更新脚本，再刷新 B 站。公开 `main` 不附带预构建的 `dist/`。

<details>
<summary>开发检查与目录结构</summary>

提交前运行：

```sh
npm run typecheck
npm test -- --run
npm run build
npm run build:dev
```

开发版输出在 `dist/dev/extension/` 和 `dist/dev/userscript/`，控制台日志以 `[时光机]` 开头；不要与生产版同时启用。Pull Request 请说明改动及验证结果。

项目使用 TypeScript、Vite、Vitest 和 jsdom；设置面板使用原生 TypeScript、Tailwind CSS 与 daisyUI，样式编译后注入 Shadow DOM，不依赖 CDN。

| 目录 | 职责 |

| `src/core/`、`src/page/` | 时间规则、收藏候选与页面内容过滤 |
| `src/playback/` | 动画片单、播放会话、公益广告与续播 |
| `src/runtime/` | 扩展和脚本适配、消息桥与页面生命周期 |
| `src/routes/`、`src/ui/` | 页面支持、设置面板与提示 |
| `extension/`、`userscript/`、`tests/` | 安装入口、清单与测试 |

</details>

- **Actions 构建**：`build.yml` 在 push 或手动运行时检查、测试并构建，提供生产 Artifact `bilibili-time-machine-release` 和开发 Artifact `bilibili-time-machine-dev`。登录 GitHub 后可从成功的 [Build 运行](https://github.com/LeKZzzz/bilibili-time-machine/actions) 下载；解压后使用 `extension/` 或 `userscript/`。
- **GitHub Release**：统一 `package.json`、`package-lock.json` 根包、`extension/manifest.json` 和 `vite.config.ts` 中的版本后，将公开改动推送到 `main`。`release.yml` 检查对应 `vX.Y.Z`：已发布则跳过，否则构建校验、上传三份生产附件后公开 Release。
- **失败重试**：可重跑或手动选择 `main` 运行。已有草稿会按原提交或已有标签补齐附件，不改写标签或已公开版本；仅推送标签不触发发布。使用内置 `GITHUB_TOKEN`，无需 PAT。
- **独立渠道**：Actions Artifacts 不等于 Release；GitHub 发布不会同步到 Greasy Fork 或扩展商店，Greasy Fork 需另行发布。
